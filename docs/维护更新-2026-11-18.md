# PDF 依赖迁移与模型 HTTPS 断连恢复

## PyMuPDF 导入名迁移

PyMuPDF 的旧导入名 `fitz` 已弃用。PDF 文本提取、OCR 页面渲染、Document AI
和启动依赖检查统一使用 `pymupdf`，并移除正文抓取模块中未使用的旧导入。
`requirements.txt` 中最低版本由 `PyMuPDF>=1.23.0` 提高到 `PyMuPDF>=1.24.0`。

更新依赖后重启程序：

```powershell
py -m pip install -r requirements.txt
```

无需安装名为 `fitz` 的独立包。迁移说明见
[PyMuPDF 官方安装文档](https://pymupdf.readthedocs.io/en/latest/installation.html)。

## 模型 HTTPS 意外断连

对于 `SSLError` 中的 `UNEXPECTED_EOF_WHILE_READING` 或
`EOF occurred in violation of protocol`，共享模型 HTTP 调用层会新建连接，
分别等待 1 秒、2 秒后重试，最多发送 3 次。最终审核同样适用，模型与请求内容保持一致。

证书校验始终开启。证书验证失败、其他 SSL 错误、读取超时和普通连接错误不会触发
这项重连规则；HTTP 错误和审核响应解析仍遵循原有逻辑。
其他调用方原有的模型回退规则保持生效。

这是针对偶发断连的恢复机制，无法消除持续的网关、代理或网络故障。
如果三次请求仍失败，审核仍标记为“审核未完成”，之前失败的记录需重新审核。
连接断开时服务端可能已经处理请求，因此重试可能产生额外模型调用费用。

## 验证

- 在 PyMuPDF 1.28.2 下生成本地 PDF，验证文本提取和页面渲染通过。
- 新增 TLS 恢复测试 3 项：断连恢复且请求一致、持续断连次数上限、其他错误不重试。
- 现有最终审核 25 项、模型遥测 11 项、可观测性 10 项测试均通过。
- TLS 测试为离线模拟，没有调用付费模型接口，也不代表线上网关已恢复。

复测命令：

```powershell
py -m unittest discover -s tests -p test_tls_recovery.py
py -m unittest discover -s tests -p test_final_review.py
py -m unittest discover -s tests -p test_model_telemetry.py
py -m unittest discover -s tests -p test_observability.py
```
